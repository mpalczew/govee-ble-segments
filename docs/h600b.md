# Govee H600B — BLE solid bulb (not a segment device)

E12 / similar A19-class RGB bulbs. Two sockets on a fixture are **two BLE peripherals**, not one segmented light.

## Identity

| | |
|---|---|
| Model | H600B |
| ADV name pattern | `GVH600B*` |
| GATT write | `00010203-0405-0607-0809-0a0b0c0d2b11` |
| GATT notify | `00010203-0405-0607-0809-0a0b0c0d2b10` |
| Encryption | **yes** — session AES-ECB(16) + RC4(4) after `e701`/`e702` |
| PSK (auth only) | `MakingLifeSmarte` (16 bytes; same family as GoveeBTTempLogger) |

Byte 19 of the **plaintext** is XOR of 0..18, then encrypt.

## Writes (plaintext before encrypt)

| Action | Prefix |
|---|---|
| Power | `33 01 01` / `33 01 00` |
| Brightness | `33 04 LL` (`LL` = 0–100) |
| Solid RGB | `33 05 0d RR GG BB` |

Phone order when turning on: **color → power on → brightness**.

There is **no** `33 05 15` segment paint. Do not send Hexa/sconce masks at these bulbs.

## Status reads

See [status-read.md](status-read.md). Per bulb:

| Field | Query | Reply |
|---|---|---|
| Power | `aa 01` | `aa 01 {0\|1}` |
| Dim % | `aa 04` | `aa 04 {0–100}` |
| RGB | `aa 05` | `aa 05 0d RR GG BB` |

`aa a5` is empty (not a segment fixture).

## Pair of bulbs

Treat each MAC as its own device. A ceiling-fan pair is two connects, two auth handshakes, two status polls. Shared “fixture brightness” in a UI is your aggregation (e.g. max of the two `aa 04` values when either is on).
